This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is an **ASP.NET Zero 13.4.0** application built on **ABP Framework 9.4.2** using **.NET 8.0**. It follows a modular monolithic architecture with Domain-Driven Design (DDD) principles and multi-tenancy support.

## Solution Files

- **ATI.All.sln** - Complete solution with all projects
- **ATI.Web.sln** - Web-focused solution (Admin + MedRevenue modules)
- **ATI.Mobile.sln** - Mobile application solution (.NET MAUI)

## Architecture

### Layered Structure

The application follows a strict layered architecture:

```
Presentation (ATI.Web.Mvc, ATI.Web.Host, ATI.Web.Public, ATI.Maui)
    ↓
Application (ATI.Application, *.Application modules)
    ↓
Domain (ATI.Core, *.Domain modules)
    ↓
Infrastructure (ATI.EntityFrameworkCore, *.EntityFrameworkCore modules)
```

### Bounded Contexts

The system is organized into multiple bounded contexts:

1. **Core (src/ATI.Core)** - Main domain with multi-tenancy, authentication, authorization, subscriptions, and payments
2. **Admin Module (Admin/)** - Company, Facility, Address management (uses "ADM" database schema)
3. **MedRevenue Module (MedRevenue/)** - Revenue cycle management
4. **Pharmacy Module (Pharmacy/)** - Pharmacy-specific functionality (experimental)

Each module follows the pattern:
- `{Module}.Domain` - Domain entities and business logic
- `{Module}.Application` - Application services and DTOs
- `{Module}.EntityFrameworkCore` - EF Core configuration and repositories
- `{Module}.Web` - Web-specific configuration and integration

### Module Integration

Modules integrate via ABP's `[DependsOn]` attribute system. Example:

```csharp
[DependsOn(
    typeof(ATIWebCoreModule),
    typeof(RevenueWebModule)
)]
public class ATIWebMvcModule : AbpModule
```

All modules share a common kernel via `ATI.Core` and `ATI.Core.Shared`.

## Naming Conventions

### Entity Naming Conventions

#### C# Entity Classes

- **Location**: `{Module}.Domain/Entities/AggregateRoots/` or `{Module}.Domain/Entities/`
- **Naming**: PascalCase, singular nouns (e.g., `Case`, `ProcedureType`, `ProcedureQuota`)
- **Base Classes**: Inherit from ABP base classes:
  - `Entity<TPrimaryKey>` - Basic entity with ID
  - `CreationAuditedEntity<TPrimaryKey>` - Adds CreationTime, CreatorUserId
  - `AuditedEntity<TPrimaryKey>` - Adds LastModificationTime, LastModifierUserId
  - `FullAuditedEntity<TPrimaryKey>` - Adds soft delete (IsDeleted, DeletionTime, DeleterUserId)
- **Multi-tenancy**: Add `IMustHaveTenant` or `IMayHaveTenant` interface for tenant filtering

Example:
```csharp
public class ProcedureType : FullAuditedEntity<int>
{
    public string Name { get; set; }
    public string Code { get; set; }
    public CategoryGroup CategoryGroup { get; set; }
}
```

#### Entity Properties

- **Naming**: PascalCase (e.g., `CaseNumber`, `TotalAmount`, `ProcedureTypeId`)
- **Foreign Keys**: `{EntityName}Id` (e.g., `ProcedureTypeId`, `FacilityId`)
- **Navigation Properties**: PascalCase, entity name (e.g., `public virtual ProcedureType ProcedureType { get; set; }`)
- **Decorators**: Use `[ForeignKey("PropertyName")]` for navigation properties

Example:
```csharp
public int? ProcedureTypeId { get; set; }

[ForeignKey("ProcedureTypeId")]
public virtual ProcedureType ProcedureType { get; set; }
```

#### Enums

- **Location**: `{Module}.Domain/Enums/`
- **Naming**: PascalCase, singular (e.g., `CategoryGroup`, `QuotaPeriod`, `CaseStatus`)
- **Values**: PascalCase with explicit integer values

Example:
```csharp
public enum CategoryGroup
{
    Pacemaker = 1,
    Defibrillator = 2,
    BatteryChangePacemaker = 3
}
```

### Database Naming Conventions

#### Schemas

- **Format**: 3-letter uppercase abbreviation (e.g., `ADM`, `REV`, `PHR`)
- **Examples**:
  - `ADM` - Admin module (Company, Facility, Address)
  - `REV` - Revenue module (Case, ProcedureType, ProcedureQuota)
  - `dbo` - Core application tables (User, Role, Tenant)

#### Tables

- **Naming**: PascalCase, singular (e.g., `[REV].[Case]`, `[REV].[ProcedureType]`)
- **Format**: `[SchemaName].[TableName]`
- **Match Entity Names**: Table names should match C# entity class names exactly

#### Columns

- **Naming**: PascalCase (e.g., `CaseNumber`, `TotalAmount`, `CreationTime`)
- **Match Property Names**: Column names should match C# property names exactly
- **Foreign Keys**: `{EntityName}Id` format (e.g., `ProcedureTypeId`, `FacilityId`)

#### Constraints

**Primary Keys:**
- **Format**: `PK_{TableName}` (auto-generated by EF Core)
- **Example**: `PK_ProcedureType`

**Foreign Keys:**
- **Format**: `FK_{ChildTable}_{ParentTable}_{ColumnName}`
- **Example**: `FK_Case_ProcedureType_ProcedureTypeId`

**Unique Constraints:**
- **Format**: `UK_{TableName}_{ColumnName}` or composite name
- **Example**: `UK_ProcedureType_Code`

**Delete Behaviors:**
- `ON DELETE SET NULL` - For optional relationships (preserve child when parent deleted)
- `ON DELETE CASCADE` - For dependent entities (delete children when parent deleted)
- `ON DELETE RESTRICT` - Prevent deletion if references exist

Example:
```sql
ALTER TABLE [REV].[Case]
ADD CONSTRAINT [FK_Case_ProcedureType_ProcedureTypeId]
FOREIGN KEY ([ProcedureTypeId])
REFERENCES [REV].[ProcedureType] ([Id])
ON DELETE SET NULL;
```

#### Indexes

**Format**: `IX_{TableName}_{ColumnName}` or `IX_{TableName}_{Column1}_{Column2}` for composite

**Examples:**
- `IX_Case_ProcedureTypeId` - Single column index
- `IX_Case_ProcedureTypeId_ProcedureDate` - Composite index
- `IX_ProcedureType_Code` - Unique index on Code

Example:
```sql
CREATE INDEX [IX_Case_ProcedureTypeId] ON [REV].[Case] ([ProcedureTypeId]);
CREATE UNIQUE INDEX [IX_ProcedureType_Code] ON [REV].[ProcedureType] ([Code]);
```

### DTO Naming Conventions

- **Location**: `{Module}.Application/Dtos/` or `{Module}.Application/{Entity}/Dtos/`
- **Naming Patterns**:
  - `{Entity}Dto` - Basic DTO (e.g., `CaseDto`, `ProcedureTypeDto`)
  - `CreateOrEdit{Entity}Dto` - Input DTO for create/update (e.g., `CreateOrEditCaseDto`)
  - `GetAll{Entity}Input` - Filter/pagination input (e.g., `GetAllCasesInput`)
  - `Get{Entity}ForViewDto` - Read-only view DTO (e.g., `GetCaseForViewDto`)
  - `Get{Entity}ForEditOutput` - Edit form output (e.g., `GetCaseForEditOutput`)

### Application Service Naming Conventions

- **Interface**: `I{Entity}AppService` (e.g., `ICasesAppService`, `IProcedureTypesAppService`)
- **Implementation**: `{Entity}AppService` (e.g., `CasesAppService`, `ProcedureTypesAppService`)
- **Location**: `{Module}.Application/{Entity}/`

### Controller Naming Conventions

- **MVC Controllers**: `{Entity}Controller` (e.g., `CasesController`, `DashboardController`)
- **Location**: `{Module}.Web/Areas/{ModuleName}/Controllers/`
- **Route**: `/[Area]/[Controller]/[Action]` (e.g., `/Revenue/Cases/Index`)

### View Naming Conventions

- **Location**: `{Module}.Web/Areas/{ModuleName}/Views/{Controller}/`
- **Main Views**: PascalCase (e.g., `Index.cshtml`, `Details.cshtml`)
- **Partial Views/Modals**: Prefix with underscore (e.g., `_CreateOrEditModal.cshtml`, `_FilterPanel.cshtml`)

### JavaScript File Naming Conventions

- **Location**: `{Module}.Web/wwwroot/view-resources/Areas/{ModuleName}/Views/{Controller}/`
- **Naming**: Match view name exactly (e.g., `Index.js`, `_CreateOrEditModal.js`)
- **Format**: camelCase for variables and functions internally

### Namespace Conventions

- **Domain**: `ATI.{Module}.Domain.Entities` or `ATI.{Module}.Domain.Enums`
- **Application**: `ATI.{Module}.Application.{Entity}.Dtos`
- **Web**: `ATI.{Module}.Web.Areas.{Module}.Controllers`

## Build Commands

### Backend

```bash

dotnet build ATI.All.sln

# Build web solution only
dotnet build ATI.Web.sln

# Build in Release mode
dotnet build -c Release

cd src\ATI.Web.Mvc
dotnet run

cd src\ATI.Web.Host
```

## Database Migrations

### Creating Migrations

```bash
cd src\ATI.EntityFrameworkCore

# Create new migration
dotnet ef migrations add MigrationName --startup-project ..\ATI.Web.Mvc
```

### Running Migrations

The `ATI.Migrator` console application handles database migrations for both host and all tenant databases:

```bash
cd src\ATI.Migrator
dotnet run
```

Migrations are stored in `src/ATI.EntityFrameworkCore/Migrations/`.

### DbContext

- **Main DbContext**: `ATIDbContext` in `src/ATI.EntityFrameworkCore/EntityFrameworkCore/`
- Inherits from `AbpZeroDbContext<Tenant, Role, User, ATIDbContext>`
- Implements `IOpenIddictDbContext` for OAuth/OIDC
- Supports multi-schema (e.g., "ADM" for Admin module)
- Connection string in `appsettings.json` → `ConnectionStrings:Default`

## API Structure

The application supports both Web API and MVC:

### Web API (REST)

- **Host**: `src/ATI.Web.Host` (standalone API server)
- **Authentication**: JWT Bearer tokens
- **Documentation**: Swagger UI at `/swagger`
- **Route Pattern**: `/api/services/{app|host}/{service-name}/{action}`

ABP automatically exposes Application Services as Web API controllers. For example:

```csharp
public class CompanyAppService : ApplicationService
{
    // Auto-generated endpoints:
    // GET /api/services/app/Company/Get
    // POST /api/services/app/Company/Create
}
```

### MVC Application

- **Host**: `src/ATI.Web.Mvc` (server-rendered UI with embedded API)
- **Views**: Razor views and pages (NOT Angular or React)
- **Route Pattern**: `{area}/{controller}/{action}/{id?}`
- **Areas**: Organized by module (e.g., `Areas/Core/`)

### GraphQL (Optional)

- **Project**: `src/ATI.GraphQL`
- **Configuration**: `appsettings.json` → `GraphQL:Enabled`
- **Endpoint**: `/graphql`
- **Playground**: `/ui/playground` (when enabled)

### Real-time

SignalR hubs available at:
- `/signalr` - Common hub (notifications)
- `/signalr-chat` - Chat functionality

## Development Workflow

### Adding a New Module

1. Create projects following the pattern:
   - `{Module}.Domain`
   - `{Module}.Application`
   - `{Module}.EntityFrameworkCore`
   - `{Module}.Web`

2. Reference the module in `ATI.Web.Mvc.csproj`

3. Add `[DependsOn(typeof({Module}WebModule))]` to `ATIWebMvcModule`

4. Register entities in `ATIDbContext`

5. Generate and run migrations

### Adding Database Entities

1. Create entity class in `{Module}.Domain`
2. Add `DbSet<Entity>` to `ATIDbContext`
3. Configure entity mapping in `OnModelCreating()` if needed
4. Generate migration: `dotnet ef migrations add EntityName --startup-project ..\ATI.Web.Mvc`
5. Run migrator: `cd src\ATI.Migrator && dotnet run`

### Creating Application Services

1. Define interface in `{Module}.Application.Shared`
2. Implement service in `{Module}.Application`
3. ABP automatically exposes as Web API at `/api/services/app/{ServiceName}/{Method}`
4. Create MVC controller in `{Module}.Web` if custom UI is needed

## Multi-Tenancy

Multi-tenancy is enabled by default:
- Each tenant can have a separate database or shared database with tenant filtering
- Tenant resolution via subdomain, header, or cookie
- Always consider tenant context when writing queries
- Use `IRepository<T>` which automatically filters by current tenant

## Authorization

Permission-based authorization system:
- Permissions defined in `AppPermissions` class
- Applied via `[AbpAuthorize(PermissionNames.Permission_Name)]` attribute
- Hierarchical permission structure
- Checked automatically in Application Services and Controllers
